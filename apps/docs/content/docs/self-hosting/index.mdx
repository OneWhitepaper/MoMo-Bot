MoMo bot's server listens on loopback by default. Agent CLIs run on the server under the account that starts them. On a native install, workspace state lives in `~/.momobot` unless you set `OMB_DATA_DIR`.

[Deploy on a VPS](/docs/self-hosting/deploy-vps) explains how to build the server from this repository, connect the desktop app, and install updates by hand. If you only need a remote Docker desktop for a bot that lives on your current computer, see [Your own VPS (BYO)](/docs/computers/byo-vps).

## Optional services

- Your chosen agent provider handles authentication and billing for its CLI or API.
- Use your own Composio project or explicitly configure a compatible broker with `OMB_COMPOSIO_BROKER_URL` for connected apps.
- Configure hosted phone and account services with `OMB_CONTROL_PLANE_URL`, or use direct local pairing. Email sign-in can use your own mail server through `OMB_SIGNIN_SMTP_URL`.
- For a compatible personal cloud, set `MOMO_CLOUD_URL` for the desktop build and `VITE_MOMO_CLOUD_URL` if you want web links to the same service.
- To use a custom catalog or announcements, set `OMB_MODEL_MANIFEST_URL` or `OMB_ANNOUNCEMENTS_URL` to a source you control.

The default app does not check the upstream project for releases or send it analytics. The web interface's [optional analytics](/docs/security/analytics) is a build-time choice.
